# 笔记库规范

> 本文件是 `02 - Notes/` 的**唯一权威规范**（原 `04 - 资源/归档规则.md` 已并入此处并停用）。
> 目录职责、命名、frontmatter、归档流程、工具配置都以本文件为准。

## 🎯 核心理念

```
收集箱  ── 快速捕获，7 天内必须归档
   ↓
学习计划 ── 系统学习路径：路线图 + 阶段笔记
   ↓
领域     ── 独立技术领域知识（不分阶段）
   ↓
项目     ── 有代码落地的实践项目：构想 + 进度 + 踩坑
   ↓
资源     ── 链接、工具、书籍、课程等收藏
```

## 📂 目录职责

| 目录 | 职责 | 子目录组织 | 不要放 |
|------|------|-----------|--------|
| **00 - 收集箱** | 快速捕获，待整理 | 不分子目录 | 已归档内容 |
| **01 - 学习计划** | 系统学习体系 | `01 - 学习计划/<领域>/` | 独立技术笔记 |
| **02 - 项目** | 项目管理 | `02 - 项目/<项目>/` | 纯技术笔记 |
| **03 - 领域** | 独立技术领域 | `03 - 领域/<领域>/` | 学习计划、进度 |
| **04 - 资源** | 资源收藏 | `04 - 资源/<类型>/` | 项目/学习笔记 |
| **05 - 模板** | Templater 模板 | 平铺，不分子目录 | 正式内容 |

其余顶层目录：`00 - 索引/`（仓库级索引入口）、`01 - Blog/`（博客文章，由博客系统监控，**勿动**）。

## 📝 命名规范

### 语言约定（全中文）

- **结构性词语一律用中文**：`学习计划`、`项目`、`领域`、`资源`、`收集箱`、`模板`、`计算机视觉`、`机器人`、`编程`、`设计`。
- **专有名词 / 缩写保留原样**：`AI算子开发`、`地平线BPU`、`RDK`、`YOLOv11部署RDKX5`、`C++核心8点详解`、`ArbotiX-M开发板`。
- 顶层 `02 - Notes/` 目录名保留英文（历史约定，被脚本引用），**不改**。

### 文件与文件夹

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 目录索引首页 | `README.md` | `计算机视觉/README.md` |
| 阶段笔记 | `NN-标题.md` | `01-图像处理基础.md` |
| 实战项目 | `实战项目.md` | `实战项目.md` |
| 资源清单 | `资源清单.md` | `资源清单.md` |
| 领域指南 | `<内容>.md` | `技术栈.md`、`行业分析.md` |
| 项目主文档 | `README.md` | `机械臂视觉抓取/README.md` |
| 收集箱临时笔记 | `YYYY-MM-DD-标题.md` | `2026-10-10-想法.md` |

**禁忌**：文件名含空格、特殊字符 `/\:*?"<>|`、超过 50 字符、同名不同位置。

> 目录名允许含空格与 `-`（如 `01 - 学习计划`），但**文件名**应尽量避免空格。

## 🏷️ Frontmatter 规范

每篇笔记（含 README、模板）首行必须是 `---`，字段统一如下：

```yaml
---
title: 标题
type: 索引 | 学习计划 | 阶段笔记 | 领域指南 | 项目 | 资源 | 收集箱
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags:
  - 标签
status: 草稿 | 进行中 | 完成
---
```

| 字段 | 必填 | 说明 |
|------|:---:|------|
| `title` | ✅ | 笔记标题（可与文件名不同，便于阅读） |
| `type` | ✅ | 取值见上表，是 Dataview 检索的主维度 |
| `created` | ✅ | 创建日期 |
| `updated` | ✅ | 最后更新日期，修改内容时同步更新 |
| `tags` | ✅ | 列表形式，一行为一个标签 |
| `status` | ✅ | `草稿`（未完成）/`进行中`（持续维护）/`完成`（稳定） |

**模板例外**：`05 - 模板/` 下文件是 Templater 载荷，其 frontmatter 会被**原样复制**到新笔记。因此模板里的 `title`/`updated` 使用 `<% tp.file.title %>`、`<% tp.date.now("YYYY-MM-DD") %>` 动态取值，**不要写死**。

## 🔀 归档决策树

```
新笔记 → 这是什么类型？

├── ❓ 不确定该放哪            → 00 - 收集箱/（待整理，最多 7 天）
├── 📚 系统学习某技术/领域      → 01 - 学习计划/<领域>/
│                                   README.md（路线图）+ NN-阶段.md + 实战项目.md + 资源清单.md
├── 🔧 某个独立技术领域的知识    → 03 - 领域/<领域>/<笔记名>.md
├── 💻 某个项目的记录          → 02 - 项目/<项目名>/README.md
├── 🔗 资源、链接、工具、课程    → 04 - 资源/<类型>/<资源名>.md
└── 💡 临时想法               → 00 - 收集箱/YYYY-MM-DD-标题.md
```

**学习笔记 vs 领域笔记**：想**系统学习**（有路线图、有进度）→ `01 - 学习计划/`；只想**记录某个技术/行业**知识（不分阶段）→ `03 - 领域/`。

## 📐 文件组织规则

### ⚠️ 避免散落文件（核心）

每个目录下的笔记都应放在**子文件夹**中，不要散落在父目录：

| ❌ 错误 | ✅ 正确 |
|--------|--------|
| `03 - 领域/AI算子开发技术栈.md` | `03 - 领域/AI算子开发/技术栈.md` |
| `02 - 项目/博客项目笔记.md` | `02 - 项目/博客系统/README.md` |
| `04 - 资源/模型量化.md` | `04 - 资源/AI模型部署/模型量化.md` |

**例外**：目录根下允许存在 `README.md`（索引页）；`02 - Notes/` 根下允许 `README.md` 与 `规范.md`。

### 双链优先

用 `[[链接]]` 而非普通 Markdown 链接，方便构建知识网络。
**推荐用裸链 `[[笔记名]]`**（Obsidian 按文件名解析，重命名文件夹时不断链）；仅在**同名冲突**时才用带路径的链接 `[[路径/笔记名|别名]]`。

### 一个笔记一个主题

避免一篇笔记混装多个不相关主题，复杂内容拆分为多篇。

## 🔄 定期归档流程

| 周期 | 动作 |
|------|------|
| 每天 | 新想法先扔 `00 - 收集箱/` |
| 每周日（5 分钟） | 清空收集箱，归档到位；更新学习计划进度 |
| 每月末（30 分钟） | 合并重复内容、删除过时笔记、检查散落文件 |
| 每季度 | 复盘整体结构、优化本规范 |

## ❓ 常见问题

**Q：一篇笔记同时属于多个领域？**
在主领域创建详细笔记，其他领域用链接引用。

**Q：收集箱笔记什么时候必须归档？**
每周日整理一次，最多保留 7 天。

**Q：笔记是单文件还是子目录？**
单个独立笔记可放子目录中；多个相关笔记必须用子目录组织；`README.md` 例外（放目录根）。

**Q：改文件夹名会断链吗？**
用裸链 `[[笔记名]]` 不会；带路径的链接会。所以改结构后需全库检索旧路径。
