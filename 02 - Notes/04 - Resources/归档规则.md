# 📋 笔记归档规则

> 本文档定义了笔记库所有笔记的归档规则和自动归档方案
> 最后更新：2026-06-03

---

## 🎯 核心理念

```
学习体系 (Learning)  ──── 完整学习路径：路线图 + 阶段笔记
        ↓
领域知识 (Areas)      ──── 独立技术领域（不分阶段）
        ↓
项目实战 (Projects)   ──── 完整项目记录
        ↓
资源收藏 (Resources)  ──── 链接、工具、规则
        ↓
快速捕获 (Inbox)      ──── 临时想法，待整理
```

---

## 📂 五大目录职责

| 目录 | 职责 | 子目录组织 | 不要放 |
|------|------|----------|--------|
| **00 - Inbox** | 快速捕获 | 不分子目录 | 已归档笔记 |
| **01 - Learning** | 完整学习体系 | `01 - Learning/<领域>/` | 独立技术笔记 |
| **02 - Projects** | 项目管理 | `02 - Projects/<项目>/` | 纯技术笔记 |
| **03 - Areas** | 独立技术领域 | `03 - Areas/<领域>/` | 学习计划、进度 |
| **04 - Resources** | 资源收藏 | `04 - Resources/<类型>/` | 项目/学习笔记 |

## 📐 文件组织规则

### ⚠️ 重要原则：避免散落文件

每个目录下的**笔记都应该放在对应的子文件夹中**，不要散落在根目录：

| ❌ 错误 | ✅ 正确 |
|--------|--------|
| `03 - Areas/AI算子开发技术栈.md` | `03 - Areas/AI算子开发/技术栈.md` |
| `04 - Resources/AI模型部署 - 板端部署.md` | `04 - Resources/AI模型部署/板端部署.md` |
| `01 - Learning/ComputerVision/01-OpenCV.md` | `01 - Learning/ComputerVision/01-OpenCV.md` ✅ |

**例外**：目录的 `README.md` 可以放在目录根下，作为索引页

### 子目录命名

```
01 - Learning/<领域>/         # 英文或简短中文
02 - Projects/<项目名>/
03 - Areas/<领域名>/
04 - Resources/<类型>/
```

### 笔记命名

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 计划/索引首页 | `README.md` | `ComputerVision/README.md` |
| 阶段笔记 | `01-标题.md` | `01-图像处理基础.md` |
| 实战项目 | `实战项目.md` | `实战项目.md` |
| 资源清单 | `资源清单.md` | `资源清单.md` |
| 领域指南 | `<内容>.md` | `技术栈.md`、`行业分析.md` |
| 资源笔记 | `<内容>.md` | `模型量化.md`、`板端部署.md` |
| 临时笔记 | `YYYY-MM-DD-标题.md` | `2026-06-03-想法.md` |

### 命名禁忌

- ❌ 文件名含空格（影响命令行操作）
- ❌ 特殊字符：`/\:*?"<>|`
- ❌ 太长（> 50 字符）
- ❌ 同名不同位置

## ⚙️ 自动归档方案

### 方案 1：Obsidian Templater 插件（推荐）

**安装**：设置 → 第三方插件 → 社区插件市场 → 搜索 "Templater"

**配置模板文件夹**：`02 - Notes/_templates/`

> 模板文件已经在 `02 - Notes/_templates/` 中创建完成

**使用方式**：

1. 在 Obsidian 中按 `Ctrl + N` 新建笔记
2. 输入模板触发命令
3. 选择模板，自动填入元信息
4. 选择保存位置

### 方案 2：QuickAdd 插件（更快捷）

**安装**：社区插件市场 → "QuickAdd"

**配置命令**：

```
命令 1: 📚 新建技术笔记
  - 自动选择分类
  - 自动使用技术笔记模板
  - 自动归档到正确位置

命令 2: 💡 快速捕获到 Inbox
  - 自动使用 Inbox 模板
  - 保存到 00 - Inbox/

命令 3: 📖 新建学习计划
  - 自动使用计划模板
  - 保存到 01 - Learning/<领域>/
```

**快捷键建议**：

| 命令 | 快捷键 |
|------|--------|
| 快速捕获 | `Ctrl + Shift + I` |
| 新建技术笔记 | `Ctrl + Shift + T` |
| 新建项目笔记 | `Ctrl + Shift + P` |

### 方案 3：Git 钩子（自动校验）

在 `.git/hooks/pre-commit` 中加入：

```bash
#!/bin/bash
# 检查笔记是否放在了正确的位置

NEW_FILES=$(git diff --cached --name-only --diff-filter=A | grep '\.md$')

for FILE in $NEW_FILES; do
  # Inbox 笔记可以放任何位置
  if [[ $FILE == *"00 - Inbox"* ]]; then
    continue
  fi

  # README.md 可以在任何目录
  if [[ $FILE == *"README.md" ]]; then
    continue
  fi

  # 检查是否在子目录中（避免散落）
  # 计算目录层级，至少需要 2 层（02 - Notes/XX/xx.md）
  DEPTH=$(echo "$FILE" | tr -cd '/' | wc -c)
  if [[ $DEPTH -lt 3 ]]; then
    echo "⚠️  笔记 $FILE 在根目录，建议放到子文件夹中"
  fi
done
```

### 方案 4：手动规则

每天 / 每周花 5 分钟做归档：

1. 打开 `00 - Inbox/`
2. 逐条笔记判断
3. 移动到正确位置
4. 更新 `01 - Learning/` 的进度

## 🆕 新增笔记的标准流程

### Step 1: 决定类型

```
这个笔记是？
├── 系统学习笔记（带阶段） → 01 - Learning/<领域>/
├── 独立技术领域 → 03 - Areas/<领域>/
├── 项目笔记 → 02 - Projects/<项目>/
├── 资源收藏 → 04 - Resources/<类型>/
└── 不确定 → 00 - Inbox/（先放这）
```

### Step 2: 命名和位置

```
01 - Learning/计算机视觉/01-新阶段.md
03 - Areas/新领域/新指南.md
02 - Projects/新项目/README.md
04 - Resources/新类型/资源.md
00 - Inbox/2026-06-03-新想法.md
```

### Step 3: 填写元信息

```yaml
---
type: <类型>
created: YYYY-MM-DD
tags: [相关标签]
status: 草稿/进行中/完成
---
```

### Step 4: 添加反向链接

在相关笔记的 README 中添加链接。

## 📌 关键约定

### 1. 一个笔记一个主题
避免一篇笔记包含多个不相关主题。复杂内容拆分为多个笔记。

### 2. 双链优先
用 `[[链接]]` 而不是普通链接，方便构建知识网络。

### 3. 元信息必填
每篇笔记都要有 YAML frontmatter，方便检索。

### 4. 定期复盘
每周回顾、每月整理、每季优化。

### 5. 文件夹即分类
**文件夹结构就是分类体系**，不要靠文件名分类。

### 6. 避免散落文件 ⭐
每个领域/类型的笔记都应该在子文件夹中，不要散落在父目录。

## ❓ 常见问题

### Q: 一篇笔记同时属于多个领域怎么办？
A: 在主领域创建详细笔记，其他领域用链接引用。

### Q: 学习笔记和领域笔记有什么本质区别？
A:
- **学习笔记**：分阶段、有路线图、有进度（`01 - Learning/`）
- **领域笔记**：独立技术指南，不分阶段（`03 - Areas/`）

### Q: 笔记是放 Learning 还是 Areas？
A:
- 想要**系统学习**某个领域（如 CV、嵌入式）→ `01 - Learning/`
- 只是想**记录某个技术/行业**知识 → `03 - Areas/`

### Q: Inbox 里的笔记什么时候必须归档？
A: 每周日整理一次，最多保留 7 天。

### Q: 笔记是单文件还是子目录？
A:
- 单个独立笔记 → 可以在子目录中（不要散落在父目录）
- 多个相关笔记 → 必须用子目录组织
- README.md 除外
